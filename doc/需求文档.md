# COC 部落管理系统 — 需求文档

> 版本：v2.0
> 更新时间：2026-08-01
> 说明：本文档汇总系统当前**已实现**的全部功能。此前 v1.2 仅聚焦"部落成员唯一性与跨部落移动"单一功能，本文档将其作为独立章节整合，并补全其余所有模块（认证与权限、数据字典、部落群组、部落、联赛、部落战、数据看板等）的需求与接口规格。

---

## 1. 产品概述

COC（Clash of Clans，部落冲突）部落管理系统面向部落联盟管理者，提供多群组（多部落联盟）隔离的数据管理能力。系统围绕"群组 → 部落 → 成员 → 联赛 / 部落战"的业务层级，支撑成员管理、联赛报名与战绩统计、部落战记录、数据看板等核心运营场景。

### 1.1 业务层级

```
群组(ClanGroup / groupNo)        ← 顶层租户，一个群组即一个部落联盟
 ├─ 部落(Clan / clanNo)           ← 群组内某个部落，逻辑主键为 clanNo
 │   └─ 成员(ClanMember / memberNo) ← 群组内成员，逻辑主键为 memberNo（全局唯一）
 ├─ 联赛(League / leagueNo)       ← 群组内联赛，含报名、战绩、部落成绩
 └─ 部落战(ClanWar / warNo)       ← 群组内单次部落战，含成员战绩
```

### 1.2 多租户隔离（关键约束）

- 所有业务数据（`biz/*` 与 `dict/*`）均携带 `groupNo` 字段，作为**租户隔离**标识。
- 除超级管理员（`sys_user.group_no` 为空）外，普通用户只能访问自己所属群组（`groupNo`）下的数据。
- `dict_group` / `dict_item`（`sys/` 下的字典与权限配置）为**全局共享**，不随群组隔离。
- 所有业务实体继承 `BaseEntity`，包含 `id`、`createTime`、`updateTime`、`deleted`（逻辑删除）公共字段。

### 1.3 通用 API 规范

- 统一前缀：`/api/...`。
- 统一响应结构 `ApiResponse`：`{ code, message, data }`，`code=0` 表示成功。
- 接口路径、前端路由、菜单 `path` 统一使用**小驼峰（camelCase）**，不使用中划线或下划线。
- 统一异常处理 `GlobalExceptionHandler`；统一跨域配置 `CorsConfig`。
- 鉴权：`JwtInterceptor` 拦截 `/api/**`（白名单除外），从请求头解析 `token` 得到 `AuthUser`，存入 `UserContext`。

## 2. 认证与系统管理

### 2.1 认证（AuthController — `/api/auth`）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/login` | POST | 用户名 + 密码登录，返回 `{ token, user }` |
| `/register` | POST | 用户注册（`RegisterRequest`） |
| `/info` | GET | 获取当前登录用户信息（需登录） |
| `/logout` | POST | 退出登录（JWT 无状态，前端清空本地 token） |
| `/assignRole` | POST | 为用户分配角色：先物理删除原关联，再全量插入 `roleIds`（空数组=清空） |
| `/changePassword` | POST | 修改当前登录用户密码（请求体 `{ oldPassword, newPassword }`） |

- 登录成功后签发 JWT（`JwtUtil.generateToken`），响应包含 `token` 与 `user`（`AuthUser` 含 userId、username、groupNo、nickname、roleCodes、permissions）。
- 密码字段 `SysUser.password` 标注 `@JsonIgnore`，不对外序列化。

### 2.2 用户管理（SysUserController — `/api/sysUser`）

继承 `BaseCrudController` 提供通用 CRUD（`page / list / get / create / update / delete`），并扩展：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/page` | POST | 分页查询（支持 `username`、`nickname` 模糊、`status` 精确、`groupId`/`groupNo` 过滤） |
| `/list` | GET | 列表查询 |
| `/get` | GET | 按 `id` 查询（回填 `roleIds`） |
| `/create` | POST | 创建用户 |
| `/update` | POST | 更新用户 |
| `/delete` | POST | 删除用户 |

- `SysUser` 字段：`username`、`nickname`、`phone`、`email`、`status`(1启用/0禁用)、`groupNo`（空=超级管理员）、`roleIds`、`roleCodes`、`permissions`（后三者的非持久化字段在查询时回填）。

### 2.3 角色管理（SysRoleController — `/api/sysRole`）

继承 `BaseCrudController` 通用 CRUD。

- `SysRole` 字段：`roleCode`、`roleName`、`status`、`remark`。角色为**全局配置**，不随群组隔离。

### 2.4 菜单与权限（SysMenuController — `/api/sysMenu`）

继承 `BaseCrudController` 通用 CRUD，并扩展：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/tree` | GET | 返回菜单树（按 `parentId` 层级组装） |

- `SysMenu` 字段：`parentId`、`menuType`(0目录/1菜单/2按钮)、`menuName`、`path`、`component`、`icon`、`permission`、`sort`。
- `permission` 字段即接口所需的权限标识，用于前端按钮级鉴权。

### 2.5 系统配置（SysConfigController — `/api/sysConfig`）

独立 CRUD（`page / create / update / delete`），**物理删除**（不继承 `BaseEntity`）。

- `SysConfig` 字段：`configName`(唯一)、`configValue`、`description`、`createdAt`、`updatedAt`、`createdBy`、`updatedBy`。
- 用于存储全局键值型配置（如计算参数等）。

## 3. 数据字典（DictGroup / DictItem）

数据字典为**全局共享**配置，用于各类状态/类型字段的中文翻译与下拉选项。

### 3.1 字典分组（DictGroupController — `/api/dictGroup`）

继承 `BaseCrudController` 通用 CRUD。

- `DictGroup` 字段：`groupCode`、`groupName`、`remark`、`status`。

### 3.2 字典项（DictItemController — `/api/dictItem`）

继承 `BaseCrudController` 通用 CRUD，并扩展：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/byGroup?groupCode=` | GET | 按分组编码获取字典项列表（前端下拉/翻译用） |

- `DictItem` 字段：`groupCode`、`itemName`、`itemValue`、`sort`、`status`。
- 系统已使用的字典分组（示例）：
  - `war_status`：部落战胜负状态（1=胜 / 2=平 / 3=败）
  - `signup_status`：联赛报名状态（1=未报名 / 2=备选报名 / 3=主动报名）
  - `war_member_status`：成员参战状态（0=不参战 / 1=参战）
  - `member_status`：成员在组状态（0=已退出 / 1=已加入）
  - `league_tier`：联赛段位
  - `apply_status`：入组申请状态（1=申请中 / 2=同意 / 3=拒绝）

### 3.3 字典翻译

响应中涉及字典值的字段（如 `winStatus`、`signupStatus`、`tierName` 等）由 Controller 通过 `byGroup` 查询回填中文名称（`tierName`/`leagueName`/`clanName` 等为 `@TableField(exist=false)` 的非持久化展示字段）。

## 4. 部落群组管理（ClanGroup）

群组是系统的顶层租户（部落联盟），由群主管理，成员通过"入组申请"加入。

### 4.1 群组管理（ClanGroupController — `/api/clanGroup`）

继承 `BaseCrudController` 通用 CRUD，并扩展：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/page` | POST | 分页查询（超级管理员看全部，普通用户看本组） |
| `/list` | GET | 列表查询 |
| `/get` | GET | 按 `id` 查询（回填 `ownerName`） |
| `/create` | POST | 创建群组（指定 `groupName`、`ownerId` 等） |
| `/update` | POST | 更新群组 |
| `/delete` | POST | 删除群组 |

- `ClanGroup` 字段：`groupNo`(群组编号/租户标识)、`groupName`、`ownerId`、`ownerName`(回填)、`intro`、`status`。

### 4.2 入组申请（ClanGroupApplyController — `/api/clanGroupApply`）

继承 `BaseCrudController` 通用 CRUD，并扩展：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/page` | POST | 分页查询（支持 `groupId`/`groupNo`、状态过滤） |
| `/list` | GET | 列表查询 |
| `/create` | POST | 提交入组申请（申请人 = 当前登录用户） |
| `/approve` | POST | 同意申请（`applyStatus`=2） |
| `/reject` | POST | 拒绝申请（`applyStatus`=3） |
| `/delete` | POST | 删除申请记录 |

- `ClanGroupApply` 字段：`groupNo`、`userId`、`applyStatus`(1申请中/2同意/3拒绝)、`username`/`nickname`/`groupName`(回填)。
- 约束：一个用户同一时刻只能存在一条"申请中"（`applyStatus=1`）的记录。
- 同意后申请人即成为该群组成员（关联到群组的成员视图）。

### 4.3 群组成员（ClanGroupMemberController — `/api/clanGroupMember`）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/page` | POST | 分页查询群组下的成员（按 `groupNo` 隔离） |
| `/list` | GET | 列表查询 |

- 群组成员视图聚合了该群组下所有部落的成员（`clan_member` 均带 `groupNo`）。

## 6. 部落成员管理（ClanMember）

> 本章为系统**核心功能**，详见第 11 章"部落成员唯一性与跨部落移动"的完整规格说明。此处仅列出模块级接口。

### 6.1 成员管理（ClanMemberController — `/api/clanMember`）

继承 `BaseCrudController` 通用 CRUD，并扩展：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/page` | POST | 分页查询（支持 `groupId`/`groupNo`、`clanNo`、`memberName`/`memberNo`、`memberStatus`、`warStatus` 过滤） |

### 6.2 成员导入（ClanMemberImportController — `/api/clanMemberImport`）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/import` | POST | 上传 Excel 导入成员（按 `memberNo`/`backupName` 去重匹配，已存在则更新、不存在则新增） |

- 导入时通过 `memberNo` 与 `backupName1~5` 识别同一成员，避免重复创建；成员跨部落移动后，`memberNo` 保持不变，仅更新 `clanNo` 与 `memberStatus`。

## 7. 联赛管理（League）

联赛是群组内周期性赛事，包含报名、成员战绩、部落成绩三个维度。

### 7.1 联赛管理（LeagueController — `/api/league`）

继承 `BaseCrudController` 通用 CRUD：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/page` | POST | 分页查询（支持 `groupId`/`groupNo`、`leagueName` 过滤） |
| `/list` | GET | 列表查询（按群组隔离） |
| `/create` | POST | 创建联赛（指定 `leagueName`、`leagueNo`、`groupNo`、`signupStart`、`signupEnd`） |
| `/update` | POST | 更新联赛 |
| `/delete` | POST | 删除联赛 |

- `League` 字段：`leagueName`、`leagueNo`(联赛编号/逻辑主键)、`groupNo`、`signupStart`、`signupEnd`。

### 7.2 联赛报名（LeagueSignupController — `/api/leagueSignup`）

继承 `BaseCrudController` 通用 CRUD，并扩展：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/page` | POST | 分页查询（支持 `leagueNo`、`clanNo`、`memberNo`、`signupStatus` 过滤，回填 `leagueName`/`clanName`/`thLevel`/`matchValue`/`combatPower`） |
| `/list` | GET | 列表查询 |
| `/batchSignup` | POST | 批量报名（`leagueNo` + `memberIds`，批量写入 `league_signup`） |

### 7.4 联赛部落成绩（LeagueClanScoreController — `/api/leagueClanScore`）

| 接口 | 方法 | 说明 |

## 9. 数据看板（Dashboard）

数据看板提供运营概览，所有统计均受 `groupNo` 租户隔离约束（DashboardController — `/api/dashboard`）。

| 接口 | 方法 | 说明 |
|------|------|------|
| `/overview` | GET | 概览统计：群组数、部落数、成员数、联赛数、部落战数（当前为全量统计） |
| `/warStat` | GET | 部落战战绩统计：按 `winStatus`(胜/平/败) 分组计数 |
| `/leagueRank` | GET | 联赛排行榜：聚合所有 `LeagueRecord`，按成员汇总 `winStars`、`actualAttacks`、`destroyRate` |

### 9.1 统计口径

- **overview**：直接对各表 `selectCount` 汇总（群组、部落、成员、联赛、部落战总数）。
- **warStat**：按 `ClanWar.winStatus` 分组计数（`null` 归为 `-1`）。
- **leagueRank**（积分算法）：`score = winStars * 3 + actualAttacks`；按 `memberNo` 聚合所有联赛的 `winStars`、`actualAttacks`、`destroyRate`，按 `score` 降序取前 10。

## 10. 通用能力

### 10.1 基础 CRUD 基类（BaseCrudController）

所有业务实体 Controller 继承 `BaseCrudController<T>`，自动获得以下统一接口（路径由子类 `@RequestMapping` 决定）：

- `/page`（POST 分页）、`/list`（GET 列表）、`/get`（GET 按 id）、`/create`（POST 新增）、`/update`（POST 更新）、`/delete`（POST 删除）。
- 分页统一返回 `{ records, total, size, current }`，支持 `current`/`size` 与字段排序。

### 10.2 文件上传与导入（CommonController — `/api/common`）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/upload` | POST | 通用文件上传，返回可访问 URL（用于头像、附件等） |

## 11. 核心功能：部落成员唯一性与跨部落移动

> 本章为系统最核心的业务规则，原 v1.2 需求文档内容，现整合为系统级文档的独立章节。

### 11.1 背景与目标

原系统允许同一真实玩家在多个部落各建一条成员记录（各自独立的 `id`），导致联赛报名、战绩统计、看板排行榜出现重复计算与数据不一致。

**目标**：以 `memberNo`（成员编号）作为同一玩家的全局唯一标识。同一 `memberNo` 在系统中**只允许存在一条记录**，玩家在不同部落之间移动时**复用同一条记录**（更新 `clanNo` 与状态），而非新建记录。

### 11.2 唯一性规则

1. **全局唯一键**：`memberNo` 在 `clan_member` 表中全局唯一（跨群组、跨部落）。
2. **新增校验**：`ClanMemberController.create` 时，若 `memberNo` 已存在且 `memberStatus=1`（已加入），返回"该成员已存在"；若已存在但 `memberStatus=0`（已退出），则复用该记录并重新加入（`memberStatus=1`，更新 `clanNo`）。
3. **别名匹配**：`ClanMember` 提供 `memberNo` 及 `backupName1~5` 备用名称。导入或录入时通过 `memberNo` 与 `backupName` 共同识别同一玩家，避免重名重复创建。

### 11.3 成员状态字段

- `memberStatus`：在组状态（0=已退出 / 1=已加入）。
- `warStatus`：参战状态（0=不参战 / 1=参战），由字典项 `war_member_status` 维护，用于联赛报名筛选。
- 成员退出部落时，`memberStatus` 置 0 但**记录保留**（`memberNo` 不变），可随时重新加入。

### 11.4 跨部落移动（核心接口：`/api/clanMember/moveOrAdd`）

玩家从部落 A 移动到部落 B 时，调用 `moveOrAdd`：

1. 以 `memberNo` 定位唯一记录。
2. 若存在且 `memberStatus=0`（已退出）：更新 `clanNo=B`、`memberStatus=1`，完成"加入新部落"。
3. 若存在且 `memberStatus=1`（已在 A）：先将 A 置为退出（`memberStatus=0`），再更新 `clanNo=B`、`memberStatus=1`，完成"跨部落移动"（同一 `id`/`memberNo` 不变）。
4. 若不存在：视为新成员，创建记录（`memberStatus=1`，`clanNo=B`）。

**效果**：无论玩家在群组内如何流转，`memberNo` 始终对应唯一一条记录，联赛报名（`league_signup` 以 `leagueNo+memberNo` 定位）、战绩（`league_record`/`clan_war_record` 以 `memberNo` 关联）、看板排行榜（按 `memberNo` 聚合）均不会重复或丢失历史。

### 11.5 与其他模块的联动

- **联赛报名**：`league_signup` 以 `leagueNo + memberNo` 唯一定位，玩家跨部落移动后，同一 `memberNo` 的历史报名/战绩自动归属到最新 `clanNo`，无需迁移。
- **战绩统计**：`league_record`、`clan_war_record` 通过 `memberNo` 关联成员，移动不影响历史战绩聚合。
- **看板排行榜**：`DashboardService.leagueRank` 按 `memberNo` 聚合，确保同一玩家战绩不重复累计。
- **导入**：`ClanMemberImport.import` 与 `LeagueImport.import` 均以统一键去重，移动后成员被识别为"更新"而非"新增"。

### 11.6 边界与校验

- 逻辑删除的成员（`deleted=1`）视为不存在，可重新创建；但同一 `memberNo` 的有效记录唯一。
- 移动/加入操作需校验目标部落 `clanNo` 存在于同一 `groupNo`（租户隔离），跨群组移动不被允许。
- 批量 `updateWarStatus` 仅影响成员的 `warStatus`，不改变归属部落。

## 12. 非功能性需求

### 12.1 技术栈

- 后端：Spring Boot + MyBatis-Plus + Java 8。
- 认证：JWT（无状态）。
- 数据库：关系型（逻辑删除 `deleted` 字段）。
- 导入：Apache POI（Excel）。

### 12.2 安全与隔离

- 所有写接口需登录（`JwtInterceptor` 校验 token）。
- 业务数据按 `groupNo` 租户隔离；超级管理员（`groupNo` 为空）可跨组管理。
- 角色/菜单/权限为全局配置，字典为全局共享。

### 12.3 命名与接口规范

- 接口路径、前端路由、菜单 `path` 统一小驼峰（camelCase），禁止使用中划线/下划线。
- 统一响应 `ApiResponse`，统一异常处理与跨域配置。

### 12.4 分页与排序

- 列表/分页接口统一返回 `{ records, total, size, current }`，支持按字段排序。
